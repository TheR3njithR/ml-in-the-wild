# Episode 3: Detect a Broken Data Pipeline Without Reading the Logs

ML in the Wild, Episode 3. QuickBasket is a **fictional** grocery-delivery company. Every number in the video comes from this folder. The data is **synthetic**, generated by `make_data.py` (seed 33).

## What this episode teaches

A green job is not the same thing as good data. We detect silent pipeline breaks from the **volume pattern** (usual same-weekday volume, plus a small calendar adjustment, plus a source-arrival check), without reading log text. A naive row-count rule and a status==SUCCESS rule are the baselines.

Journey: Data → Model → Decision → Action → Feedback.

## Run it

```bash
python -m pip install -r requirements.txt
./run_all.sh
```

`run_all.sh` rebuilds the synthetic data, the baseline, the detector, the 16 March 2026 morning report, the feedback comparison, and the charts. It should finish in under a minute.

## What you get

- `make_data.py` — generator. Writes `data/pipeline_daily.csv` and friends.
- `pipeline_guard.py` — shared features and the expected-volume residual detector.
- `01_baseline_rules.py` — status rule and naive row-count rule.
- `02_detect.py` — expected volume + source-fill, with training-only thresholds.
- `03_decide_and_act.py` — morning green / amber / red report (default date 2026-03-16).
- `04_feedback_loop.py` — first-week labels and a champion vs challenger test.
- `05_charts.py` — the figures used in the video.
- `data_dictionary.md`, `CHALLENGE.md`.

## Data files

Every CSV in `data/` is well under 5 MB. If a chart PNG is missing from a GitHub checkout, run `./run_all.sh` to regenerate it.

## Important rule

`incident_labels.csv` and `incident_log.csv` are the answer key. The detector does not use them at prediction time. Features are the finished job (rows, usable rows, sources arrived) and the calendar, never the log text, never the hidden healthy volume.
