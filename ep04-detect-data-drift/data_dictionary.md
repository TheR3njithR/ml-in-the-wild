# Data dictionary (synthetic)

All files are generated by `make_data.py` (seed 41). Nothing is real customer data.

## `daily_demand.csv`

One row per day, 1 December 2024 to 30 April 2026.

| Column | Meaning |
|---|---|
| date | Calendar day |
| dow | Monday = 0 … Sunday = 6 |
| is_weekend | 1 on Friday and Saturday (this market's weekend) |
| is_holiday | 1 on a small set of public holidays |
| temp_c | Temperature in Celsius (used by the demand model, not by the drift monitor) |
| promo_rate | Share of beverage SKUs on promo that day (known in the morning from the marketing calendar) |
| express_share | Share of orders placed on an express slot, trailing mix |
| app_share | Share of orders placed in the app, trailing mix |
| aov | Average order value, in the local currency |
| new_zone_share | Share of volume from the new Sharjah Edge zone (zero until 14 April 2026) |
| competitor_index | Observed competitor discount intensity, 0 to 1 |
| lag_7, roll_28 | Last week's units, and a 28-day trailing mean (no leakage of today's units) |
| units | Actual beverage units fulfilled that day. These arrive with a 7-day lag. |
| split | train / test / production, for convenience. Scripts recompute the cut dates. |
| label_available_on | The morning on which this day's actuals are known |

## `incident_log.csv`

Answer key for the planted shift. The model and the monitor never see this file at prediction time.

## `known_changes.csv`

Two dated marketing / network changes (Summer Sips promo, Sharjah Edge zone). Used only in the feedback discussion.
